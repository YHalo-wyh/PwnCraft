# PwnCraft 增强路线

评估日期：2026-10-26。代码基线：远端 `main` 的 `180034a`，叠加本地 Seccomp 页面、社区 Patcher 集成。

## 当前基础

主程序为 Electron Workbench，Python 桥负责目标状态、静态分析、堆模型和补丁操作，WSL 提供工具与调试运行环境。

Binary 页已有漏洞扫描、EXP 骨架生成、GDB 偏移验证和逐候选实测入口；`features/synth` 已提供策略、生成器和运行时验证。新合入的 `features/autopwn` 另外实现了 ELF 识别、有界 stdin 探测和人工 EXP 候选并发检查。增强工作应先统一两套流程的任务和证据接口，避免重复开发生成器。

## 优先级与验收

| 优先级 | 工作项 | 直接收益 | 验收条件 |
| --- | --- | --- | --- |
| P0 | 统一后台任务与取消机制 | 长时间扫描和补丁任务运行时，仍可切换目标、查看日志和取消任务 | 长任务运行期间 `ping` 可响应；取消后清理子进程；旧目标结果不会写入新工作区 |
| P0 | 补齐干净检出的可复现环境 | 其他机器和 CI 能恢复相同依赖、训练资源和启动行为 | 干净检出可安装、跑测试和冒烟；训练语料来源、哈希与下载方式可追溯 |
| P1 | 统一 Synth / AutoPwn 工作流 | 从一个入口查看路线缺口、运行候选和复验结果 | 单个受支持样本完成导入、识别、偏移实测、生成、运行、独立复验和证据导出 |
| P1 | 补丁前后双向复验 | 同时确认攻击失效与正常服务可用 | 同一基线下保存原始攻击、正常交互和补丁后两组结果；失败产物无法标记为已验证 |
| P1 | 建立菜单与 TCP Harness | 扩展当前 stdin 探测能实际覆盖的题型 | 含提示等待、菜单选择、二进制发送和超时的交互脚本可重复回放 |
| P2 | 独立 holdout 与能力统计 | 用可重现结果指导新策略开发 | 按漏洞类型、架构和 glibc 版本分别报告误报、漏报、成功复验率和耗时 |

## P0：后台任务

`pwncraft/electron_bridge.py` 的主循环按行调用 `bridge.handle()`，普通 RPC 处理仍为串行。部分自动 triage 已使用后台线程，但社区 Patcher 等耗时调用会同步等待子进程。主进程默认 300 秒超时只负责结束等待，无法表示任务进度或取消执行。

实现范围：

- 增加 `job_start / job_status / job_cancel`，返回稳定的 `job_id`，统一排队、运行、完成、失败、取消状态。
- 将只读分析与工作副本写入分别调度；同一工作副本的变更串行执行。
- 任务绑定目标 SHA-256、工作副本修订号和参数摘要，切换目标或应用补丁后拒绝采纳过期结果。
- 保存进度事件、工具版本、命令参数、日志和产物目录，支持进程重启后查看历史任务。
- 对子进程输出实施读取阶段的容量限制，并在取消、超时和异常路径统一清理进程组。

入口文件：`pwncraft/electron_bridge.py`、`pwncraft-electron/main.js`、`pwncraft-electron/renderer/pages.js`、`pwncraft/features/autopwn/engine.py`。

## P0：可复现环境

当前 `pwncraft-electron/package-lock.json` 被根目录 `.gitignore` 排除，npm 依赖恢复缺少受版本控制的锁文件。训练目录另有 8 条 `160000` Git 条目，但仓库缺少对应 `.gitmodules` 映射，`git submodule status` 会直接失败。

处理范围：

- 提交依赖锁文件，通过 `npm ci` 恢复依赖；记录 Python、Node、Electron、WSL 发行版和工具版本。
- 对 8 个训练 Git 条目逐项确定管理方式：使用带 URL 和固定 revision 的正规子模块，或改为可重建的语料下载清单。
- 将本地绝对路径语料清单改为语料根目录加相对路径，保留完整 SHA-256 和来源说明。
- 为 Windows 桥和 Electron 冒烟增加对应 CI；保留现有 Linux Python 与真值回归。
- 将版本显示统一从桥返回的版本读取，减少渲染层硬编码。

## P1：合并 AutoPwn 与 Synth 的执行和证据

`features/synth/pipeline.py` 已具备 `verify_all_exploits()`；Binary 页已有对应操作。`features/autopwn/engine.py` 的候选检查接受人工清单，Electron 桥只暴露只读能力与识别接口，执行仍在 CLI。

第一阶段限定在已有生成器支持的 i386 / amd64 样本，复用 Synth 的目标事实、策略状态和 EXP 生成器，将 AutoPwn 的候选调度接入任务接口。每条候选都展示缺失事实、执行条件、运行结果和复验次数。

成功判定需要区分三类证据：脚本输出满足正则、目标运行时观察到控制流或内存效果、独立环境复验成功。当前 AutoPwn 的正则检查只能证明第一类；Synth 的 marker 判定也应记录目标通道与独立复验，避免将脚本自行打印的字符串当作目标执行证据。

首批验收包含成功样本、缺失 gadget、未测出偏移、仅打印 marker 的假 EXP，以及一次成功但复验失败的候选。任务结果统一保存目标与 EXP 哈希、运行参数、依赖版本、退出状态、输入和输出摘要。

## P1：补丁复验

社区 Patcher 已支持 scratch 副本、产物差异和显式采纳。后续在采纳前增加产物解析、架构与入口检查、工具退出状态检查，并显示新增段、权限变化和安全策略差异。

每条补丁绑定两套回放：攻击回放用于确认已知利用失效，正常交互回放用于确认菜单、文件读写和服务协议仍可用。复验均从相同基线开始，分别记录原始 ELF、工作副本和最终导出文件的哈希。补丁器异常退出但留有产物、文件损坏、服务回归失败时，结果保持待复核状态。

入口文件：`pwncraft/features/patch/patchers/`、`pwncraft/features/patch/patch_core.py`、`pwncraft-electron/renderer/patch.js`。

## P1：交互 Harness

AutoPwn 当前探测对象为 stdin，固定样本生成不包含覆盖率反馈；Synth 已有菜单识别和前置步骤，可作为脚本格式的基础。

统一交互描述支持 `expect / send / sendline / recv / timeout`，明确原始字节、换行、编码与本地进程或 TCP 通道。保存最小化后的崩溃输入和完整交互顺序；按崩溃栈、故障地址和执行阶段聚类，避免只按 signal 合并不同缺陷。此后再接入覆盖率反馈，评测新增覆盖和可复现崩溃数量。

## P2：训练与能力统计

保留现有人工真值、严格重放与反馈规则机制。目录名推断的标签作为弱标签，独立人工分析和运行复验结果作为验证集。训练集与 holdout 按题目来源及变体分组去重，避免同一题的改名副本跨集合。

展示指标包括：函数与调用点覆盖、各漏洞类型误报和漏报、策略可生成率、运行命中率、独立复验成功率、正常服务回归通过率，以及每个阶段的耗时。每个失败样本归到可定位的缺口，例如函数边界恢复、菜单前置状态、栈迁移、泄漏推导、glibc 差异或调用约定。

## 推荐实施顺序

1. 完成后台任务协议和可复现环境，保留当前功能行为。
2. 用一个受支持的栈题打通统一的 Synth / AutoPwn 任务及证据展示。
3. 建立正常交互回放，并接入补丁前后复验。
4. 扩展菜单和 TCP Harness，再按 holdout 失败分布增加策略。
